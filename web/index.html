Measured on the selected index, at the k, sparsity, read length and alphabet above: computed on demand in this browser (a download of about 8 MB once, then each setting once), for protein and reduced alphabets. Where short k-mers are held by most groups, precision is measured on fewer read pairs to stay within the browser's memory, down to a few tens, so treat it as rough there; recall per target always uses every query. Plots across k show the k computed so far at these settings. Reads have no translation or errors. Each k-mer a read shares with a group is kept at 1 in m, simulated over 8 hash salts, so very sparse settings rest on few hits; one index is one draw, shown as a range where measured. Scores are kfp's evidence: each key's bits (composition less log2 of the groups holding it) less about 9 bits per hit after the first, for every frame's windows. Floors below a key's bits change nothing, so low floors only matter at small k or for promiscuous keys. Chance from 2 more frames is added. These indexes are one representative per MGnify90 unit and denser than the release, so values do not carry over to it. Database size and representative share above do not change this panel: it describes the bundled set. At k 5 and 6, and on reduced alphabets, relatives' identities are often unknown and count as wrong, so "or a relative" reads low. Recall per target tiles reads across each target, so reads of one target share its conservation and hash; it counts every read over the floor on the true group, under either "A read keeps" rule, and takes even abundance. Precision per target has not been tested above 6 read pairs per target, and probably reads high at great depth, since it does not count other groups reached by reads elsewhere on a target. Chance grows with the index.

Model: k-mer anchors on group representatives, with conserved and variable blocks fitted to kfp's 90%-AAI table (recall ceiling 0.96), and a conservation rate shared by each read fitted to the simulation. Index size assumes 225 residues per representative and 6 bytes per posting; the representative share is held fixed as the database grows, which is a stand-in until the scale profile is measured. Chance assumes 3 frames per read, with a measured correction at protein k 5–9 and composition alone (a lower bound) elsewhere. Reduced alphabets raise identity by the share of substitutions staying within a class (from BLOSUM62, scaled 1.6× to fit simulated reads on three alphabets), and lower chance by class frequencies. Nucleotide mode reads identity as nucleotide identity, assumes 3 letters per residue and uniform bases, and uses conservation fitted on protein with no codon structure, so treat it as a rough guide.

Uses k, sparsity, read length and pairing from the top of the page. A substitution removes every key overlapping it. The fewest that remove all keys are shown in red, and are the worst case at that number. For protein, a base change reaches a residue at about 3 × the rate per base, × 0.75 non-synonymous, less substitutions staying within a class on a reduced alphabet; nucleotide mode uses the rate per base. Uniform changes place them at random across the read, while the model's conserved blocks and rate per read concentrate them, and include kfp's 0.96 ceiling, so the two differ at the same identity. A pair's mates are drawn separately, and the chance of no key takes them as independent; minimizers take gaps as uniform.

Analyse a protein set

Runs in this browser; files are not uploaded. Sets over 20 M residues are sampled at random to stay within wasm's memory. "Independent" is what independent residues with this set's composition would give. Decoys are one random half's sequences reversed, matched to the other half. Between halves counts matches between sequences of the two halves, so with homologues it is far above chance. Above k 7 in a set this small, a few k-mers dominate the decoy rate.
